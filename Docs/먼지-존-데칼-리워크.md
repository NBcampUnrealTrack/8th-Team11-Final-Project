# 먼지 존 데칼 리워크

1단계 도로 청소 존(`ACWWorkZone_Dust`)의 겉모습과 진행 연출을 다시 만든 작업 기록.

## 1. 배경

이전 구현은 이랬다.

- 존 `Area` 와 1:1 로 맞춘 **직사각형 데칼 한 장**
- 렌더 타깃(`CoverageMask`)에 매 프레임 붓 자취를 찍어 **지나간 자리만 국소적으로 지움**
- 머티리얼은 Deferred Decal / Translucent / **Unlit**, Emissive 만 출력

두 가지가 문제였다.

**"먼지 스티커" 로 보인다.** 원인이 세 개 겹쳐 있었다.

1. Unlit 이라 조명 계산을 아예 안 탄다. 바닥은 빛을 받는데 먼지만 안 받으니 위에 얹힌 그림으로 읽힌다.
2. 실루엣이 직선이다.
3. 모든 존이 같은 텍스처를 같은 자리에서 시작해 복붙 티가 난다.

**부분 지우기가 "쌓인 먼지" 로 안 읽힌다.** 붓이 지나간 자리만 뻥 뚫려서, 먼지를 쓸어낸 게 아니라 스티커를 긁어낸 것처럼 보였다.

목표는 두 가지였다. 살짝 입체감이 있는 진짜 먼지처럼 보일 것, 그리고 싱크홀이 아스팔트를 맞고 단계별로 작아지듯 **단계별로 줄어들** 것.

## 2. 방향 결정

### 메시로 가지 않았다

`CWWorkZone_Dust.h` 에 원래 적혀 있던 논거가 그대로 유효하다. 먼지는 싱크홀 균열·페인트 자국과 같은 자리를 다투는데, 반투명 평면 메시로 두면 층 순서를 정할 방법이 없다. 반투명은 데칼 패스보다 뒤에 그려지고 디퍼드 데칼은 GBuffer 를 고치므로, 먼지가 항상 데칼 위로 올라가 균열을 덮어버린다. 데칼끼리는 `SortOrder` 로 층을 명시할 수 있다.

**입체감은 메시 형상이 아니라 조명 반응에서 나온다.** Unlit → Default Lit 으로 바꿔 Normal 을 GBuffer 에 쓰는 것이 이 작업의 핵심이었다.

### 구조

```
존 하나 = 데칼 패치 N장 (기본 8)
  ├─ 지터 격자로 배치, 회전/크기/UV/밝기 전부 다름
  ├─ 머티리얼의 블롭 마스크가 각 패치를 둥글고 우둘투둘하게 깎음
  └─ 진행도가 오르면 정해진 순서로 하나씩 걷힘 + 남은 것은 전체적으로 옅어짐
```

## 3. 텍스처

출처는 Fab 의 `Dirt_Ground` 텍스처 세트(1K, 9장). `/Game/CrossWalk/Painting/Zone/Materials/Textures/` 에 3장만 만들었다.

| 에셋 | 설정 | 내용 |
| --- | --- | --- |
| `T_DustGround_BaseColor` | sRGB, TC_Default, MaxSize 512 | 흙 색 |
| `T_DustGround_Normal` | sRGB 끔, TC_Normalmap, 512 | 알갱이 요철 |
| `T_DustGround_ORH` | sRGB 끔, TC_Masks, 512 | **R=AO, G=Roughness, B=Height** |

`ORH` 는 소스 3장을 RGB 로 합친 것이다. 샘플러가 5개에서 **3개**로 줄고, 세 채널을 다 쓰면서도 텍스처 샘플은 한 번이다. 이 환경에는 Python 도 ImageMagick 도 없어서 PowerShell `System.Drawing` 의 LockBits 로 직접 합쳤다.

### 소스 통계 — 왜 이게 중요했나

각 맵의 픽셀 분포를 실제로 재봤다.

| 맵 | 평균 | 표준편차 | 용도 |
| --- | --- | --- | --- |
| AO | 0.881 | 0.094 | 불투명도 그레인 |
| Height (Displacement) | 0.281 | 0.083 | **가장자리 브레이크업** |
| Roughness | 0.849 | **0.026** | Roughness 출력 |
| BaseColor | 0.451 | 0.026 | 색 |

처음에는 가장자리를 흔드는 데 `AO - 0.5` 를 썼는데, AO 평균이 0.881 이라 이 식은 **변화를 만드는 대신 블롭을 일정하게 줄이기만 했다.** 중심값이 신호의 평균과 맞아야 위아래로 고르게 흔들린다. 그래서 신호를 Height 로 바꾸고 중심값을 파라미터(`EdgeBreakupMid`)로 뺐다.

Roughness 는 표준편차가 0.026 뿐이라 브레이크업 용도로는 못 쓴다.

## 4. 머티리얼 — Substrate 함정

> **이 프로젝트는 `r.Substrate=True` 다 (`Config/DefaultEngine.ini`).
> 데칼 머티리얼에서 `BaseColor` / `Normal` / `Roughness` 핀은 연결해도 조용히 무시된다.**

에러도 경고도 없다. 알베도가 흰색인 것처럼 렌더돼서 "머티리얼은 나오는데 색만 뿌연" 상태가 되고, 불투명도와 텍스처 샘플링은 멀쩡히 동작하기 때문에 원인을 엉뚱한 데서 찾게 된다.

### 진단 과정

1. 화면 픽셀을 재서 유효 알파와 색을 역산했다. 아스팔트 위 `(125,125,138) → (185,179,169)`, 흰 정지선 위 `(245,244,242) → (230,228,222)`. 두 식을 풀면 α ≈ 0.55, 먼지 색 ≈ `(221,217,201)` — 거의 흰색. 흙 BaseColor 는 sRGB 115 인데 화면엔 220 이 나왔다.
2. `DustTint` 를 순수 빨강으로 바꿨다. 픽셀이 안 바뀌었다.
3. 파라미터 캐시 문제일 수 있으니 **상수 빨강을 `MP_BaseColor` 에 직결**했다. 그래도 안 바뀌었다.
4. 카메라를 몇 cm 옮겨 리드로우를 강제했다. 배경 픽셀은 바뀌었는데 먼지 색은 그대로였다 → BaseColor 경로가 죽어 있다는 확정.

### 정답 경로

```
Substrate Slab BSDF ──► Substrate Convert To Decal ──► Front Material
  Diffuse Albedo                      ▲
  Roughness                           │
  Normal                        Coverage ◄── 불투명도
  Emissive Color
```

불투명도는 `MP_Opacity` 가 아니라 **`ConvertToDecal` 의 Coverage** 로 들어간다. 바꾼 뒤 아스팔트 위 먼지가 `(184,179,169)` 중성 회색에서 `(218,203,179)` 황갈색으로 살아났다.

### Coverage 식

```
Coverage = Blob × (1 − ClearedPct × GlobalThin) × MaxOpacity × PatchFade × Lerp(1, AO, DirtBreakup)

Blob = 1 − smoothstep(1 − EdgeSoftness, 1, d + saturate(Height − EdgeBreakupMid) × EdgeBreakup)
d    = |uv − 0.5| × 2        (데칼 자기 UV. 중심 0, 내접원 가장자리 1)
```

`saturate` 가 중요하다. 이게 없으면 브레이크업이 음수가 되어 `d` 를 당기고, 데칼 경계에서도 마스크가 살아남아 상자에 잘린다(→ 6절). `saturate` 로 오프셋이 항상 ≥ 0 이면 `d ≥ 1` 에서 Blob = 0 인 것이 **파라미터 값과 무관하게 보장된다.**

### 파라미터 (전부 `Dust` 그룹)

| 이름 | 기본 | 누가 넣나 | 뜻 |
| --- | --- | --- | --- |
| `ClearedPct` | 0 | C++ | 존 전체 진행도 |
| `PatchFade` | 1 | C++ | 이 패치 하나의 알파 |
| `Tiling` | 1 | C++ | 패치별 UV 배율 |
| `UVOffset` | 0,0 | C++ | 패치별 텍스처 위치 |
| `DustTint` | 흰색 | C++ | 패치별 밝기 지터 |
| `MaxOpacity` | 1 | 아티스트 | 전체 진하기 |
| `GlobalThin` | 0.5 | 아티스트 | 진행도가 남은 패치를 옅게 하는 정도 |
| `DirtBreakup` | 1 | 아티스트 | AO 로 농담을 갉는 정도 |
| `EdgeSoftness` | 0.35 | 아티스트 | 블롭 가장자리 폭 |
| `EdgeBreakup` | 1.8 | 아티스트 | 가장자리 우둘투둘함 |
| `EdgeBreakupMid` | 0.22 | 아티스트 | 브레이크업 임계값 (Height 분포에 맞춘다) |
| `NormalStrength` | 1 | 아티스트 | 요철 세기 |
| `RoughnessMin/Max` | 0.7 / 1.0 | 아티스트 | Roughness 범위 |
| `EmissiveBoost` | 0 | 아티스트 | 그늘 시인성 비상구 |

`EmissiveBoost` 는 Lit 전환의 부작용 대비다. 건물 그림자 안의 먼지가 안 보여서 "여기 할 일 남았다" 가 전달되지 않으면 0.05~0.15 로 올려 바닥 대비를 확보한다.

## 5. C++

```
Painting/Data/CWDustPatch.h      패치 하나의 상태 (USTRUCT)
Painting/Zone/CWWorkZone_Dust.h  존 액터
```

### 걷어낸 것

`CoverageMask` 렌더 타깃, `BrushStampMaterial`, `M_BrushStamp` 에셋, `PaintAt()`, `ProjectToLocalUV()`, UV 축 뒤집기 토글 3개, 그리고 **`Tick` 전체**. 존마다 매 프레임 렌더 타깃에 그리던 비용이 통째로 없어졌다.

### 패치 배치

`BuildPatches()` 가 **지터 격자**로 뿌린다. 완전 난수면 뭉치는 자리와 빈 자리가 같이 생겨 존이 고르게 더러워 보이지 않는다.

```
Aspect  = AreaExtent.X / AreaExtent.Y
Columns = clamp(round(sqrt(PatchCount × Aspect)), 1, PatchCount)
Rows    = ceil(PatchCount / Columns)
```

칸마다 한 장씩 놓고 칸 안에서 흔든다(`PatchJitter`). 패치는 칸보다 `PatchOverlap` 배 크게 잡는다 — 블롭 마스크가 가장자리를 둥글게 깎으므로 넉넉히 겹쳐야 한 덩어리로 읽힌다.

패치마다 달라지는 것: 투영축 회전 0~360°, 가로세로 독립 스케일 지터(→ 블롭이 정원이 아니라 타원), `UVOffset`, 밝기 지터. 색조는 안 흔든다. 흔들면 먼지가 아니라 얼룩으로 보인다.

### 결정론적 시드 — 네트워크 모델

배치는 **리플리케이트하지 않는다.** 시드를 존 이름의 문자열 CRC 에서 뽑으므로 모든 기계가 같은 배치를 각자 만들어낸다. 네트워크로 오가는 것은 진행도 하나뿐이다.

```cpp
const uint32 NameHash = FCrc::StrCrc32(*GetName());
return static_cast<int32>(NameHash ^ (static_cast<uint32>(LayoutSeed) * 2654435761u));
```

`FName` 의 해시를 쓰면 안 된다. 이름 테이블 등록 순서에 따라 값이 달라져서 서버와 클라이언트가 다른 배치를 만든다. 문자열 CRC 는 내용만 본다.

`LayoutSeed` 는 배치가 마음에 안 들 때 다시 굴리는 번호다.

### 단계별 걷힘

```
q      = clamp(Progress / CompleteThreshold, 0, 1)
Span   = 1 / (N − 1 + PatchFadeWindow)
Start  = ClearSlot × Span
Fade   = 1 − clamp((q − Start) / (Span × PatchFadeWindow), 0, 1)
```

`CompleteThreshold`(0.95)를 100% 로 보고 늘려 잡는다. 진행도 1 을 기준으로 하면 마지막 패치가 걷히기 전에 존이 완료돼서 "완료라는데 먼지가 남아 있다" 가 된다. `Span` 은 마지막 패치가 정확히 `q = 1` 에서 끝나도록 역산한 값이다.

`PatchFadeWindow` 가 창구다. 1 보다 작으면 패치 사이에 틈이 생겨 단계감이 세고, 1 이면 틈 없이 이어지고, 1 보다 크면 여러 장이 동시에 옅어진다. 기본값 0.7 의 틈은 8장 기준 전체 청소 시간의 4% 정도다.

`ClearSlot` 은 배치와 같은 시드로 Fisher-Yates 셔플한다. 배열 순서 그대로 두면 격자 왼쪽 위부터 차례로 사라져서 "쓸었다" 가 아니라 "한 줄씩 지웠다" 로 보인다.

다 걷힌 패치는 `SetVisibility(false)` 로 렌더에서 빠진다. **청소가 진행될수록 그릴 데칼이 줄어든다.**

### VFX 훅

```cpp
UFUNCTION(BlueprintNativeEvent, Category = "Dust")
void OnDustPatchCleared(int32 PatchIndex, const FVector& PatchLocation);
```

패치 하나가 완전히 걷힌 순간 호출된다. BP 에서 흙먼지를 터뜨리는 자리다(`ACWSinkhole::OnFillProgressed` 와 같은 패턴). 이 연출이 없으면 패치가 조용히 사라져서 무슨 일이 일어났는지 안 보인다. "단계별로 줄어든다" 를 각인시키는 건 사실상 이 한 방이다.

## 6. 작업 중 잡은 버그

### (1) 런타임에 먼지가 아예 안 나옴

패치를 `OnConstruction` 에서만 만들었다. 그런데 패치 컴포넌트는 `RF_Transient` 라 PIE 월드로 복제될 때 빠지고, 레벨에 배치된 액터는 런타임에 `OnConstruction` 이 다시 돌지 않는다. **에디터 뷰포트에는 먼지가 보이는데 플레이하면 데칼이 0개**였다.

→ `BeginPlay` 에서도 `BuildPatches()` 를 부른다. 기존 것을 먼저 지우므로 두 번 불려도 결과가 같다.

Simulate 로 실제로 띄워 컴포넌트를 세어보지 않았으면 못 잡았을 버그다.

### (2) 존마다 흙 알갱이 굵기가 다름

`Tiling` 을 **언스케일** `Area` 익스텐트로만 계산하고 액터 스케일을 안 봤다. `Area` 는 어느 존이나 100×50 인데 배치할 때 액터 스케일(0.33~1.0)로 크기를 조절하므로, 작은 존일수록 텍스처가 촘촘하게 찍혔다. Stage_01 만 유독 곱고 Stage_02 는 얼룩덜룩했던 원인.

→ 월드 크기로 계산한다. 가로세로가 다를 때는 기하평균을 쓴다(배율이 스칼라 하나라 한 축에 맞추면 다른 축이 늘어난다. 기하평균이면 반씩 갈린다).

```cpp
const float WorldSizeX = 2.f * HalfSizeX * FMath::Abs(ActorScale.X);
const float WorldSizeY = 2.f * HalfSizeY * FMath::Abs(ActorScale.Y);
Patch.Tiling = FMath::Sqrt(WorldSizeX * WorldSizeY) / FMath::Max(DustTextureWorldSize, 1.f);
```

검증: Stage_02 의 7개 존 56장 전부 실효 텍스처 크기 70.0cm 로 동일.

### (3) 바닥에 지워지지 않는 사각형이 남음

가장자리 브레이크업이 `(Height − Mid) × Breakup` 이라 **음수가 될 수 있었다.** Height 가 낮은 픽셀에서 `d` 를 최대 −0.35 당겨, 데칼 상자 끝(`d = 1`)에서도 마스크가 75% 살아남은 채 상자 모양으로 잘렸다.

→ `saturate` 를 끼워 브레이크업이 **안쪽으로만** 작용하게 했다. 오프셋이 항상 ≥ 0 이므로 경계에서 0 인 것이 수학적으로 보장된다.

한 번에 안 끝났다. 한쪽으로만 바꾸니 브레이크업이 너무 약해져(임계값 0.32 는 픽셀의 31% 만 걸림) 이번엔 동그란 물방울무늬가 됐다. 임계값을 0.22(면적의 절반 이상)로 내리고 세기를 1.8 로 올려 우둘투둘함을 되찾았고, `PatchOverlap` 을 1.35 → 1.7 로 키워 패치끼리 이어지게 했다.

### (4) 에디터 프리뷰가 게임과 다름

MID 를 `BeginPlay` 에서만 만들어서, 에디터 뷰포트의 패치는 머티리얼 기본값(`Tiling=1`, `UVOffset=0`)으로 그려지고 있었다. 배치하는 사람이 보는 알갱이 굵기가 실제 게임 화면과 달랐다.

→ `CreatePatchMaterials()` 를 `BuildPatches()` 안으로 옮겼다. 이제 에디터와 런타임이 같은 그림을 본다.

### (5) Prototype 맵의 존이 머티리얼을 못 받음

`DustMaterial` 은 원래 비어 있었고 `M_DustGround` 는 `DustDecal` 컴포넌트에 직접 물려 있었다. 패치를 런타임에 만들게 되면서 컴포넌트가 없어졌으므로 프로퍼티로 옮겨야 했다. BP CDO 는 고쳤는데, **Prototype 의 존 8개는 `DustMaterial = None` 개별 오버라이드를 들고 있어서 기본값을 안 따라왔다.** 머티리얼 없는 데칼이 엔진 기본 데칼로 그려졌다.

→ 인스턴스에 값을 직접 넣었다. `reset_properties` 류로 오버라이드를 걷어내면 BP CDO 가 아니라 **C++ 기본값(nullptr)** 으로 되돌아가므로 쓰면 안 된다.

KTY(4), Stage_01(3), Stage_02(7) 은 오버라이드가 없어 정상이었다. Prototype 만 문제였다.

## 7. 성능

| 항목 | 내용 |
| --- | --- |
| Tick 제거 | 존마다 매 프레임 돌던 렌더 타깃 드로우가 사라짐 |
| 자연 감소 | 걷힌 패치는 `SetVisibility(false)` → 청소할수록 렌더 비용이 **내려감** |
| 텍스처 | `MaxTextureSize` 512 + ORH 채널 패킹 (샘플러 5 → 3) |
| 머티리얼 | 패치 전부 같은 부모의 MID → 셰이더 퍼뮤테이션 1개 |
| 데디케이티드 서버 | `BuildPatches` 가 즉시 반환. 데칼을 아예 안 만듦 |
| POM | 쓰지 않음. ORH 의 B 채널에 Height 는 들어 있으니 필요하면 켤 수 있음 |

패치를 잘게 쪼개면 데칼 개수만큼 드로우 셋업이 붙는다. 덮는 총 면적은 그대로라 픽셀 비용은 거의 같으니, **실루엣이 충분히 부서지는 선에서 멈추는 것이 이득**이다. 6~10 장 권장.

## 8. 튜닝 가이드

### 존 크기는 액터 스케일보다 BoxExtent 로

패치 격자의 열/행 수를 **언스케일** 익스텐트의 종횡비에서 뽑는다. 액터 스케일 `(0.5, 1)` 같은 걸 쓰면 로컬에서는 정사각 칸인데 월드에서는 2:1 로 찌그러진 칸이 된다. `BoxExtent` 로 조절하면 격자가 실제 모양을 따라간다. 액터 스케일은 `(1,1,1)` 로 두는 것을 권장.

### PatchCount 는 넓이에 비례해서

알갱이 굵기는 존 크기와 무관하게 일정하지만 **덩어리 크기는 아니다.** 지금 보기 좋은 설정이 칸 하나 ≈ 50cm 이므로:

```
PatchCount ≈ (가로 cm × 세로 cm) / 2500
```

기본 200×100 존이 정확히 8 이다. 400×200 로 키우면 32 정도.

### 그 외

- 먼지가 굵고 얼룩덜룩하면 `DustTextureWorldSize` 를 낮춘다 (작을수록 곱다).
- 물방울무늬처럼 따로 놀면 `PatchOverlap` 을 올린다.
- 가장자리가 밋밋하면 `EdgeBreakup` 을 올린다. `EdgeBreakupMid` 는 **텍스처를 갈아끼우면 새 Height 평균에 맞춰 다시 잡아야 한다.**
- `BoxExtent` 를 바꾸면 `OnConstruction` 이 자동으로 다시 돌아 뷰포트에 바로 반영된다.

## 9. 남은 작업

- **빗자루 애니메이션** — 보류. 상체 슬롯 루프 몽타주로 붙이면 되고, `IsWorking()` 과 `GetHeldTool()` 이 이미 리플리케이트되므로 ABP 게이트만으로 충분하다. 청소 동작 에셋이 없는 것이 blocker.
- **먼지 VFX** — `OnDustPatchCleared` 훅은 나와 있다. Niagara 에셋만 만들면 붙는다.

## 10. 알려진 문제

프로젝트의 데칼 도메인 머티리얼 4개 중 3개가 4절과 **같은 Substrate 문제**를 안고 있다. `MP_FrontMaterial` 없이 레거시 핀만 연결돼 있어 알베도가 흰색으로 렌더될 것이다.

| 머티리얼 | 연결된 출력 | 상태 |
| --- | --- | --- |
| `M_DustGround` | FrontMaterial | 고침 |
| `M_SinkholeCrack` | BaseColor, Roughness, Opacity | **미해결** |
| `M_SinkholeHole` | BaseColor, Roughness, Opacity | **미해결** |
| `M_Arrow_Decal` | BaseColor, Opacity | **미해결** |

Prototype 맵에서 싱크홀이 검은 원 + 흰 후광으로 보이는 것이 그 증상으로 추정된다. 셋 다 `Slab BSDF → ConvertToDecal → FrontMaterial` 로 같은 방식으로 고칠 수 있다.
